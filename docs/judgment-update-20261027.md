# Thought-led judgment update — 2026-10-27

SEA's entrypoint now leads with a model of the situation rather than an ordered lifecycle checklist. The core asks the agent to reason from origin/ownership, contextual meaning, invariant guarantees and evolution, selecting only dimensions that can change a consequential decision. These are transferable lenses, not fixed answers, a mandatory questionnaire or instructions to produce an internal reasoning transcript.

The existing requirements, architecture, data/algorithm, design, implementation and delivery material is preserved in [engineering-workflow.md](../sea/references/engineering-workflow.md). The main skill routes to that material and the specific references only when relevant. Lightweight requests remain lightweight; stateful and consequential work retains its applicable guarantees and verification.

No new independent model behavior comparison was run for this update. User-reported incidents were design inputs, not independently reproduced bugs in their original systems. Proposed transfer cases are recorded in [judgment-cases.json](../tests/judgment-cases.json) with an explicit unexecuted status. Outcome evidence must come from captured runs and artifacts, not from the agent repeating philosophical terms or completing more documents.
